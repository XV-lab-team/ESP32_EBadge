## 2. 硬性边界

### 2.1 本包要解决什么

- 目标板上的 AW9523 能被 I2C 写到（RST 后 ACK）
- `io_virtual_task` 起来后，调用 `io_virtual_gpio_set` / `io_virtual_led_set` 能改变对应引脚
- 之后由目标工程自己定义逻辑 ID，并在业务里调用这两个 API

### 2.2 本包不负责什么

- 不移植教具的电机/舵机/故障注入/HMI/Flash/绞盘业务
- 不要求目标工程使用教具的 `bsp.h` / `log.h` / `mapping.h`
- 不修改目标工程的 CubeMX 生成代码（由用户用 CubeMX 配 I2C 和 RST GPIO；AI 不要手改 `Core/`，除非目标仓库另有约定）
- **不**把虚拟 IO 用于高频翻转信号（PWM 仍走 TIM）

### 2.3 调用约定（与本教具一致）

```c
HAL_StatusTypeDef io_virtual_gpio_set(vio_gpio_id_t id, uint8_t level);
/* level: 0=low, nonzero=high */

HAL_StatusTypeDef io_virtual_led_set(vio_led_id_t id, uint8_t brightness);
/* brightness: 0~255 */
```

返回值：`HAL_OK` / `HAL_ERROR`（非法 id 或队列未建）/ `HAL_BUSY`（队列满）。  
调用方**只投递队列**，不要自己调 `aw9523_*` / `exio_*`。

**禁止**在 ISR / `vTaskSuspendAll` / 临界区内调用带超时的 `io_virtual_*`（内部 `xQueueSend(..., 20ms)`）。

## 3. 编码

| 路径 | 编码 | AI 读法 |
|------|------|---------|
| `*.md`、`src/`、`glue/` | UTF-8 | 按 UTF-8 |
| `examples/本工程_*` | GB2312/GBK | 中文注释可能乱码；以 md 为准 |

写目标工程源码时，**跟随目标仓库的编码约定**，不要把教具的 GB2312 强加给 UTF-8 工程。

## 4. 常见失败（先看再改）

| 现象 | 先查 |
|------|------|
| `exio_init` 失败 / I2C timeout | SCL/SDA 上拉、引脚、速率、RST 是否真的拉低再拉高；AD 地址是否写对 |
| 编译找不到 `hi2c2` / `EXIO_RST_*` | 在 `glue/io_virtual.c` 改 `VIO_I2C` / `VIO_RST_PORT` / `VIO_RST_PIN` |
| 编译找不到 `I2C_HandleTypeDef` | `src/aw9523_port.h` 里 `#include "i2c.h"` 或目标 `main.h` |
| GPIO 没变化但 I2C 成功 | 脚表 `chip_num`/`pin` 与原理图不一致；枚举下标和数组下标错位 |
| 两路功能互相干扰 | 同一芯片同一物理脚被两个 cfg 占用（GPIO↔GPIO 或 GPIO↔LED） |
| 队列满 `HAL_BUSY` | 调用太密；本包默认队列 64；禁止在 SuspendAll 里 set |
| LED 亮度寄存器乱 | 不要自己按脚号写 DIM；必须走 `aw9523_set_pin_ledval`（DIM 映射是乱序的） |
| GCR / P0 推挽没生效 | `ledmode_isel` 写成了 **0**：本驱动此时**不写 GCR**。Bring-up 用 1~3 |

## 5. 与本教具工程的关系

- 教具运行中的代码在 `USER/Chip/aw9523.*`、`USER/APP/exio.*`、`USER/APP/io_virtual.*`
- 本目录是拷贝 + 说明，给**别的工程**用
- 教具产品规则禁止改 `USER/Chip/`；本包的 `src/aw9523.c` 是给目标工程的可编译副本，行为与教具一致
- `io_virtual_chip_test_task` 只在 `examples/本工程_io_virtual.c`，是诊断任务，**默认不要创建**（会和正式任务抢 I2C）
