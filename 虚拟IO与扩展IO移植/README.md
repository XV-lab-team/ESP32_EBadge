# 虚拟 IO / 扩展 IO 移植包（给接手 AI）

本目录是一份**自包含移植包**：源码 + 说明。  
目标是把本教具工程里已经跑通的 **AW9523 芯片驱动 + exio 封装 + io_virtual 队列任务** 接到**另一个 STM32 + HAL + FreeRTOS** 工程。

**只读本文件夹即可移植。** 不要去改教具仓库里的 `USER/Chip/aw9523.*`、`USER/APP/exio.*`、`USER/APP/io_virtual.*`（那是产品库/业务，禁改）。

---

## 0. 你现在该做什么

1. **先读** `00_给接手AI.md`（编码、边界、禁令）
2. 再读 `01_架构与模块说明.md`
3. 再读 `02_HAL与I2C引脚.md`
4. 按 `03_移植步骤.md` **一层一做**
5. 改脚表时以 `05_配置表与逻辑编号.md` 为准
6. 用 `06_验收清单.md` 自测后再说「移植完成」

文件清单见 `04_文件清单.md`。

## 1. 一句话架构

```
业务调用 io_virtual_gpio_set / io_virtual_led_set
        → FreeRTOS 队列（调用线程不做 I2C）
        → io_virtual_task 写 aw9523 缓存
        → exio_apply → aw9523_apply_output
        → I2C 主机写 AW9523 寄存器
```

三层不要打穿：

| 层 | 模块 | 本包位置 | 改不改 |
|----|------|----------|--------|
| L1 | AW9523 芯片驱动 | `src/aw9523.*` | 默认不改行为 |
| L2 | 扩展 IO 封装 | `src/exio.*` | 默认不改 |
| L3 | 虚拟 IO（逻辑编号 + 任务） | `glue/io_virtual.*` | **按目标板改配置表** |
| 板级 | I2C / RST / 日志 | `src/aw9523_port.h` | **必须按目标板填** |

---

## 2. 拷什么、不拷什么

| 拷 | 不拷 |
|----|------|
| `src/` 全部（驱动 + `aw9523_port.h`） | 教具 `USER/BSP/`、`USER/Formula/log.h`、`Core/` |
| `glue/io_virtual.*` 当板级草稿 | `examples/本工程_*` 整文件覆盖目标（里面有教具脚表和 `log.h`/`bsp.h`） |
| 目标工程自己的逻辑 ID / 脚表 | 教具 `uav_fault` / `uav_exec` / 故障注入 |

`examples/` 只是「本教具新 PCB 三片 AW9523 怎么绑脚」的参考，**不要整文件覆盖目标工程**。

## 3. 编码（读源码前必看）

| 文件 | 编码 |
|------|------|
| 本目录全部 `.md`、`src/*`、`glue/*` | **UTF-8**（源码注释以英文为主） |
| `examples/本工程_*` | **GB2312 / GBK**（从教具 `USER/` 原样拷贝） |

`examples/` 里中文注释若显示成乱码，是工具按 UTF-8 误读，**不是文件坏了**。逻辑以本目录 md 和 `examples/README.md` 为准。

写目标工程源码时，**跟随目标仓库的编码约定**。

## 4. 来源

- 芯片：AW9523B（I2C GPIO/LED 扩展，最多 4 片 × 16 脚）
- 本包来源工程：无人机教具 STM32G474 + HAL + FreeRTOS + Keil ARMCC
- 教具跑通配置：I2C2 Fast ~300 kHz，RST=PC7，**3** 片（地址 `0xB0` / `0xB2` / `0xB6`）
