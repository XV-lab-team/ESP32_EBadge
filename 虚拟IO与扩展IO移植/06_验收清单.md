# 06 — 验收清单

移植者逐项打勾。全部通过才能对用户说「虚拟 IO / 扩展 IO 已移植完成」。

---

## A. 编译

- [ ] `src/` 5 个文件已加入目标工程并编译
- [ ] `glue/io_virtual.c` / `.h` 已加入编译
- [ ] Include Path 能找到 `aw9523.h` / `exio.h` / `io_virtual.h` / `aw9523_port.h`
- [ ] 已改 `VIO_I2C`、RST 脚，不再依赖教具独有的 `bsp.h`/`log.h`（除非目标工程自己就有）

## B. 硬件与 init

- [ ] CubeMX：I2C 主机 + RST 推挽已生成（AI 未手改 `Core/`，或目标仓库允许的改法）
- [ ] SCL/SDA 有上拉
- [ ] 复位后 RST 被 `aw9523_init` 拉低再拉高
- [ ] `exio_init` 返回 `HAL_OK`（或日志无 `failed`）
- [ ] 每片 8 位地址与 AD 一致；I2C 写有 ACK

## C. 单脚功能

- [ ] `io_virtual_gpio_set(第一个 GPIO, 1/0)` 能在芯片封装脚上测到高低
- [ ] 若使用 LED 模式：亮度 0 熄、非 0 亮（或电流可测）
- [ ] 调用返回 `HAL_OK`（任务已创建且队列未满）

## D. 配置表

- [ ] `vio_*` 枚举顺序与 cfg 数组一致
- [ ] `chip_num` 为 0 基且 `< 实际片数`
- [ ] 无同脚双占用
- [ ] `ledmode_isel` 为 1~3（GCR 会写入）

## E. 任务与禁令

- [ ] `io_virtual_task` 栈足够（教具 2048 字）
- [ ] 未在 ISR / `vTaskSuspendAll` 里调 `io_virtual_*`
- [ ] 未创建 `io_virtual_chip_test_task` 与正式任务长期抢 I2C
- [ ] 虚拟 IO 未用于 PWM/高频信号

## F. 明确不要验收的（本包范围外）

- 教具故障注入、电机继电器语义、串口屏、Flash KV
- `uav_fault` / `uav_exec` 行为
- 教具新 PCB 与目标板网名是否相同

---

## 失败时回看

| 失败项 | 文档 |
|--------|------|
| 编译缺句柄/类型 | `02` 宏；`aw9523_port.h` |
| I2C timeout / NACK | `02` 上拉、地址、RST |
| init OK 脚不变 | `05` chip/pin/下标 |
| `HAL_BUSY` | `00` 队列；任务是否已跑 |
| LED 乱 | `05` DIM 乱序；走 API |
| GCR/推挽无效 | `01` `ledmode_isel!=0` |
