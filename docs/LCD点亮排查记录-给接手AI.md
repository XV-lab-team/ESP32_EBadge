## 1. 硬件与驱动是否匹配（已核对）

### 匹配（芯片驱动选对了）

| 项目 | 屏规格 | 固件 |
|------|--------|------|
| IC | ST77916 | `esp_lcd_st77916` v2.0.2 |
| 接口 | QSPI，无 DC | `use_qspi_interface=1`，`dc_gpio_num=-1` |
| 写像素首字节 | 规格书第 9 节 `first byte=0x32` | 驱动 `LCD_OPCODE_WRITE_COLOR = 0x32` |
| 写寄存器 | 1 线 addr | 驱动 opcode `0x02` |
| 分辨率 | 360×RGB×360 | `LCD_H_RES/V_RES = 360` |
| QSPI 脚 | D0–D3 / SCL / CS | GPIO4/5/6/7 / 15 / 16 |
| 背光 | LED-A | GPIO17 PWM，高电平亮，默认 95% |

结论：**不要换成 ST7789 或普通 4 线 SPI。** 问题不在芯片型号。

### 不匹配 / 风险

| 项目 | 说明 |
|------|------|
| 厂商初始化表 | 规格书**没有** init 表。同一颗 ST77916、不同玻璃的 `0xF0` 厂商页不同。 |
| 曾用 VoCat 表 | ESP-VoCat **UE018HV** 用 `0xF0=0x28`（Arduino 标 1.5 寸）。T180BV 是 **1.8 寸**。 |
| 色深 | 16-bit 和 18-bit（实验 E 的 QIO、实验 R 的一线）都没点亮成功。**一线 18-bit 已失败，不要再试。** |
| RESX | 规格要硬复位。仓库 `LCD_PIN_RST=NC`。用户加过手动 RST，花屏依旧。 |
| GRAM | **SWRESET 不清 framebuffer**。断电/拔 USB 才会丢残留。 |
| 原理图 | 仓库没有 PCB 原理图。 |

组件实现（只读参考）：

`C:\Users\Admin\AppData\Local\Espressif\ComponentManager\Cache\service_d92d8f1e\espressif__esp_lcd_st77916_2.0.2_c0a565af\esp_lcd_st77916_spi.c`

- 命令：`opcode 0x02 << 24 | cmd << 8` → 总线上 `02 00 <cmd> 00`
- 像素：`opcode 0x32 << 24 | 0x2C << 8`，`tx_color` 时 ESP32 对数据阶段加 `SPI_TRANS_MODE_QIO`
- `bits_per_pixel=16` → COLMOD `0x55`，2 字节/像素
- `bits_per_pixel=18` → COLMOD `0x66`，3 字节/像素
- `draw_bitmap`：每次都发 CASET + RASET + RAMWR(`0x2C`)，`x_end`/`y_end` 是开区间，寄存器里写 `end-1`
- panel IO 会按 `spi_trans_max_bytes`（常见约 4092）切 DMA 段，段之间 `SPI_TRANS_CS_KEEP_ACTIVE`
- `tx_color` 异步；`tx_param` 会先 `get_trans_result` 收完上一笔再发命令

日志里这句可以忽略，两次都是 `0x55`：

```
W st77916_spi: The 3Ah command has been used and will be overwritten by external initialization sequence
```

驱动先发 `0x3A=0x55`，自定义 init 末尾再发一次。

### 晚间：实验 G–N（本会话）

#### 实验 G — 用户描述「一个像素分裂成多个」

- **画面**：1.8 寸表 + 整屏红之后，用户感觉像素被拆开。
- **分析**：规格是 RGB 垂直条纹，纯红近看会像细竖条；也可能是子像素没合成，或写显存只落了稀疏点。
- **决定**：改测试图，不要再整屏纯红。

#### 实验 H — 左黑 / 右白 / x=90 绿竖线 / (45,180) 红点

- **改**：`lcd_fill_rect` + `draw_bitmap` 条带刷。
- **用户现象**：满屏一个一个小点，点之间黑底；**右侧最上面有一块纯白**。
- **当时解读**：很像一次 DMA 只写对了开头（约 4KB ≈ 180 宽时约 11 行白）。
- **后验（实验 P）**：满屏小点 + 黑底就是「隔点隔行」在花 GRAM 上的样子，**不是** DMA 只写了开头。
- **3Ah 警告**：用户问过。 harmless，见第 1 节。

#### 实验 I — 每次 1 行 + `on_color_trans_done` 等 DMA

- **改**：`LCD_FILL_LINES=1`；信号量等像素 DMA 完再复用缓冲。
- **用户现象**：**还是一样**（顶上白、其余散点）。
- **结论**：不是「大块 DMA 切段」单独能解释的。若每行一次 `0x2C` 且 RASET 生效，右半应整块变白。

#### 实验 J — 用户怀疑坐标；改用 `0x2C` + `0x3C` 连续写行

- **改**：窗口只设一次 0–359；第 0 行 `RAMWR 0x2C`，其余 `RAMWRC 0x3C`；仍是左黑右白+绿线+红点。
- **用户现象**：**还是之前那个样子**。
- **结论**：要么 `0x3C` 这颗 IC 不认（CS 拉高后继续写失败），要么整屏看起来像旧图；**同一套左黑右白花屏时无法分辨有没有烧新固件**。

#### 实验 K — 顶 20 行绿 + 中 20 行红（换颜色）

- **改**：不再画左黑右白。`lcd_fill_rect(0,0,360,20,绿)` 再 `(0,180,360,20,红)`。
- **用户回报**：仍说顶上「一半黑一半白」。
- **结论（后验）**：用户当时看到的半黑半白 **不是这版绿/红条**，而是 **GRAM 里更早左黑右白测试留下的第 0 行**。不能据此说 K 没烧进去，也不能说 K 写出了半黑半白。

#### 实验 L — `LCD_FW coord-oneshot-v1`：一次 `0x2C` 写底部 y=280..359，红/绿/蓝/白各 20 行

- **log 已确认烧进去**（用户贴了 `coord-oneshot-v1 发送完成` 和心跳）。
- **用户现象**：问题仍在。**除了「这一行」以外，其它都是随机色，判断是驱动芯片里的残留。**
- **结论**：
  - 用户判断对：**软复位不清 GRAM**，随机色 = 没写过/旧数据。
  - 顶上半黑半白 = 更早「左黑右白」的 **y=0 一行**，出现在物理最上 → **y=0 在顶上，不是最后一行，不是 MY 把原点翻到顶。**
  - 本次 oneshot 要写的是底部 80 行色带。用户没看到底部分色带 → **这次 `0x2C` 基本没把新像素写进可见 GRAM**（或写到屏外 y=360 窗口）。那条「好线」很可能仍是旧残留，不是 L 写出来的。

#### 实验 N — `LCD_FW 4c-fill-v1`：不用 `0x2C`，全屏窗口 + `0x4C` 填红，等 2 秒，invert off

- **动机**：绕开 QSPI `0x32` 写像素，走和 init 一样的 `tx_param`/`0x02`。上午实验 B 只等 10ms 会截断，这次等 2000ms。
- **用户现象**：**更糟糕。连最基本的半黑半白那一行也没有了。**
- **结论**：
  - `0x4C` **确实动了 GRAM**（把旧的那一行有效数据也冲掉了）。
  - 但 **没有** 把 0–359 整窗填成均匀红。
  - 再次证明：**不要用全屏 `0x4C` 当点亮手段**（和实验 B 一致，加长延时也救不了）。
  - 可能把窗口/扫描弄乱，或内部按 R/G/B 分路填、停在错误状态。

#### 实验 O — `LCD_FW 1wire-rdbk-v1`：一线 `0x02` 写像素 + `RAMRD`

- **改**：停全屏 `0x4C`；init 后重设窗口 0–359；invert off；y=0 一行洋红、y=180 起 20 行青，走 `tx_param`/`opcode 0x02`/`0x2C`（不用四线 QIO）；读 `RDDID 0x04` 和 `RAMRD 0x2E`。
- **log（已确认烧进去）**：
  - `RDDID 0x04: 00 7F 7F 7F 00 00 00 00`（不像完整芯片 ID，dummy 周期可能不对，**不能**据此说芯片错）
  - `RAMRD`：`7f f8 1f f8 1f f8 1f ...` → dummy `0x7F` + 写入的洋红 RGB565 总线字节 `F8 1F`
- **用户现象**：找不到洋红条/青带，感觉面板没驱动起来。
- **结论（当时）**：
  - **一线 `0x2C` 已经把像素写进 GRAM，读回完全对得上。** 不是写失败。
  - 圆屏 y=0 一行几乎看不见。当时以为 y=180 青带看不见 = 玻璃完全没扫 GRAM。
  - 窗口卡在 y=360 可以排除（能读回 y=0 刚写的洋红）。
  - D1–D3 接反不再能解释「整屏不像测试图」：这次根本没用四线数据。
- **后验（实验 P 之后）**：青带很可能不是「没扫」，而是 **一行 720 字节被显示通路当成两行甚至更多**，GRAM y=180 映射到屏外。实验 O 的「像没驱动」= 稀疏点 + 测的条带落在看不见的地方。

#### 实验 P — `LCD_FW 1wire-full-yellow-v1`

- **改**：一线整屏填黄 `(255,255,0)` 即 RGB565 `0xFFE0`、总线 `FF E0`；读 `0x0A RDDPM` / `0x0B MADCTL` / `0x0C COLMOD`；再 `RAMRD` 中线。
- **用户原话**：「第一行，每隔一个点就有一个黄色点，然后隔一行，就又一行是这样的。」
- **含义**：
  - 面板 **已经在根据 GRAM 显示**，不是没驱动、不是纯 init 电压全黑。
  - 这和实验 G/H 的「像素分裂成多个」「小点之间黑底」是同一类空间抽样，以前误判成 DMA 只写了开头或 GRAM 全是残留。
  - **横向**：黄的两个字节 `FF`（很亮）和 `E0`（很暗）很像被当成两个点 → 隔点黄。
  - **纵向**：隔行才重复，像只扫了偶数 gate，或双 gate 只打进一半。
  - 若「一行 GRAM = 两行玻璃」，则实验 O 写在 y=180 的青带会落到 360 行以外，正好解释「找不到两条线」。

### 本晚：实验 Q–T（本会话）

#### 实验 Q — `LCD_FW 1wire-full-white-v1`

- **改**：一线 16-bit 不动，整屏改纯白 `0xFFFF`（总线 `FF FF`），验证字节拆点。
- **用户原话**：「看着是从上面看第二行，有一行白色的点，间距确实变小了。」
- **结论**：横缝变密，**`FF/E0` 被拆成两个点基本成立**。竖向仍稀疏。圆屏最顶一行几乎看不见，以能看到的那一行为准。

#### 实验 R — `LCD_FW 1wire-18bit-ylw-hline-v1`

- **改**：`COLMOD 0x66`，3 字节/像素，整屏黄 `FC FC 00`，y=176 起 8 行洋红横线（用户要求加横线好分析）。
- **用户原话**：
  - 「第一行是间隔较大的黄点，隔一行是间隔较小的白点，其他都是无用的。」（多半是 P+Q 的 GRAM 残留）
  - 之后确认就是这版代码：「最上面一行是有间隔的黄色点，其他都是没有像素点的。」
- **结论**：**一线 18-bit 失败。** 洋红横线没出现；其余全黑。不要再试 18-bit / `0x66`。

#### 实验 S — `LCD_FW 1wire-16bit-cyan-hline-v1`

- **改**：退回 16-bit `COLMOD 0x55`，整屏青 `(0,255,255)` + y=176 红横线。颜色全新，避免和旧黄/白搞混。init 仍是 `st77916_180`。
- **用户原话**：「现在的情况是就一行是青色的像素点，有间隔；其他行无用，继续给我改初始化……不要做重复的改动。」
- **结论**：16-bit 一线仍能在玻璃上画出当前测试色（青点），但 **只有顶上一行**；中间红线不可见。下一刀只换 init。

#### 实验 T — `LCD_FW init-idf-default-v1`（已回报）

- **改**：只换 `lcd_init_cmds.h` 为乐鑫 `vendor_specific_init_default`（栅极 `0x80` 起 `0x38`，不是 180 的 `0x48`）。测试图仍是青底+红横线。
- **用户原话**：「背景还是黑屏。从上往下：有好几行有间隔的彩色的点，而且都有行间隔，颜色也不一样。」
- **结论**：比 S 的「一行青点」多扫了几行，栅极 `0x38` 比 180 的 `0x48` 稍接近，但横拆点 + 竖隔行还在。颜色不一像青 `07 FF` / 红 `F8 00` 仍被拆成单字节，再叠 GRAM 残留。**不要退回 180。** 公开三套（VoCat / 180 / IDF 默认）用尽。

#### 实验 U — `LCD_FW init-hd18004-v1`（已回报，整圆点亮）

- **改**：只换 init 为 HD18004C18 1.8 寸供应商表（TFT_eSPI#3915）。同属 `0xF0=0x28` 但 **不是 VoCat**。测试图洋红底+绿横线，**invert off**（实验 O/P 习惯）。
- **用户原话**：「现在看是全屏绿色，中间有一行很粗的粉色还是红色的线。」
- **结论**：**HD18004C18 就是这块 T180BV 能用的表。** 全屏纯色 + 中间一条完整横线 = 栅极/源极/16-bit 都对了。洋红↔绿是 `INVON` 极性：洋红反相=绿，绿反相=洋红/粉。不是 RGB/BGR，不要再换 init。供应商自己也在表末开 `INVON`。

#### 实验 V — `LCD_FW invert-on-v1`（**当前固件，用户已确认**）

- **改**：只把测试图 `invert_color(false)` 改成 `true`。init 表、颜色、一线 16-bit 都不动。绿线仍是 y=176 起 8 行。
- **用户原话**：先确认「对现在是的」（整圆洋红+绿线）。又问绿线多宽 → **8 像素高 / 横向 360 / 约 1 mm**。并要求「你这次没问题，写入到 md」。
- **结论**：点亮完成。这块屏 **必须 INVON**。不要关 invert，不要换 init。

## 6. 关键代码行为（避免重复踩坑）

### `0x4C`

- `0x4D/0x4E/0x4F` 为填色 R/G/B（实验里红用 `0xFC,0,0`）。
- 官方：窗口 **y=360 一行**（`0x2B = 0x01,0x68,0x01,0x68`），`0x4C=1` delay 10ms，`0x4C=0`，再把 `0x2A/0x2B` 拉回 `0–359`。
- **禁止**全屏窗口 + `0x4C=1` 当点亮（10ms 和 2s 都失败；2s 还冲掉了仅存的一行残留）。

### `0x2C` 像素写入

- `draw_bitmap` → CASET/RASET + `0x2C` + QSPI `0x32` + QIO（四线）。
- **一线验证（实验 O）**：`tx_param` + opcode `0x02` + `0x2C` **能**把 RGB565 写进 GRAM，`RAMRD` 一致。
- RGB565 要 `bswap` 成总线上高字节先。洋红 `0xF81F` 总线 `F8 1F`；黄 `0xFFE0` 总线 `FF E0`；白 `0xFFFF` 总线 `FF FF`；青 `0x07FF` 总线 `07 FF`；红 `0xF800` 总线 `F8 00`。
- 实验 P：整屏黄在玻璃上是 **隔点 + 隔行**。实验 Q：白点间距变小。实验 S：只有一行间隔青点。
- 一线 18-bit（实验 R）不能点亮，已停。
- `tx_color` 异步；已加 `on_color_trans_done`。逐行等 DMA **不能**单独修好花屏。
- `0x3C`（RAMWRC）在本板上 **没有** 观察到能把后面的行补上。
- QSPI 读 opcode `0x0B`。`RAMRD` 首字节常见 dummy `0x7F`。

### invert

- HD18004 / 180 / IDF 表有 `0x21`。供应商注释：INVON 是 color correction。
- `lcd_init` 里 `invert_color(true)`。实验 O–U 测试图又 `invert_color(false)`。
- **实验 U：** invert off 时玻璃是绿底+粉/红线 = 写入洋红+绿的反相。这块常黑 IPS **需要 invert on**。
- **实验 V 已确认：** `invert_color(true)` 后整圆洋红、中间绿线。以后默认保持 INVON。绿线 8 像素高。

### GRAM

- 数据手册：`SWRESET` **不影响**内置 framebuffer。
- 顶上半黑半白 = 旧测试图第 0 行残留的可能性很大。
- 要用「有没有写出新数据」当判据时：换颜色、换位置、看 `LCD_FW` 日志，**优先 `RAMRD`**，最好掉电再上电。
- 圆屏不要用 y=0 单行当可见性测试。
- 若显示侧把 2 字节当 2 个点，则 **GRAM 的 y 与玻璃的 y 不是 1:1**。写在 y=180 的条带可能完全在屏外。可见性测试必须整圆填色。

### VoCat vs 180 vs 组件默认 vs HD18004（认表）

```
VoCat / 1.5 寸：     0xF0=0x28, 无 0x76, 0xB0=0x69, 栅极 0x80=0x48   已花（A–E）
1.8 寸 / 180：       0xF0=0x08, 0xF2=0x08, 0x9B=0x51, 栅极 0x80=0x48   已花（S 一行青点）
IDF 组件默认：       0xF0=0x08, 栅极 0x80=0x38，源极 C0=0x22           已花（T 多行间隔彩点）
HD18004C18：         0xF0=0x28, 0x76=0x0F, 0xB0=0x52, 栅极 0x48+行号 0x04, C0=0x65  **已点亮（U）**
Waveshare 1.85C：    0xF0=0x28, 0xB0=0x56, DD/DE=0x4F                 不必再试（U 已成功）
```

仓库当前是 HD18004C18。都不是金逸晨 T180BV 官方表。规格摘要里「init 来自 esp_vocat 同规格屏」已过时，不要再抄那句。**HD18004 ≠ VoCat**，不要当成重复。
