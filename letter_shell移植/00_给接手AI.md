## 2. 硬性边界

### 2.1 本包要解决什么

- 在目标 MCU 的 **Debug 串口** 上出现 letter-shell 横幅和提示符  
- 输入 `help` 能列出命令；`hello`（胶水草稿自带）能打印  
- 之后由目标工程自己加业务命令

### 2.2 本包不负责什么

- 不移植教具的电机/舵机/故障/HMI/Flash  
- 不要求目标工程使用教具的 `USART_bsp`  
- 不修改目标工程的 CubeMX 生成代码（由用户用 CubeMX 配 UART；AI 不要手改 `Core/`，除非目标仓库另有约定）

### 2.3 命令函数约定（与本教具一致）

本包 **`SHELL_AUTO_PRASE == 0`**。命令必须是：

```c
int your_cmd(int argc, char *argv[]);
```

- `argc` **含命令名**；`argv[0]` 是命令名，参数从 `argv[1]` 起  
- 返回值会打印（`SHELL_DISPLAY_RETURN == 1`）  
- **禁止**打开 `SHELL_AUTO_PRASE`：本包 `shell_ext.c` 的 `shellExtRun()` **只处理 `argc==1`**，带参数的命令会全部返回 `-1`

## 3. 编码

| 路径 | 编码 | AI 读法 |
|------|------|---------|
| `*.md`、`glue/` | UTF-8 | 按 UTF-8 |
| `src/`、`examples/本工程_*` | GB2312/GBK | 中文注释可能乱码；以 md 为准 |

写目标工程源码时，**跟随目标仓库的编码约定**，不要把教具的 GB2312 强加给 UTF-8 工程。

## 4. 常见失败（先看再改）

| 现象 | 先查 |
|------|------|
| 串口完全没字 | UART 引脚/波特率/TX 轮询标志；`shell.write` 是否接到同一口 |
| 有乱码横幅 | 波特率或终端编码；G474 教具 Debug 是 **2 Mbps 8N1**，目标板按自己 Cube 配置 |
| 有提示符但 `help` 只有 `help`/`cls` | **命令段被链接器丢掉** → 必读 `05` |
| `help` 后死机/复位 | shell 任务栈太小（教具用 **512 字**） |
| CPU 100% | 误把 `SHELL_TASK_WHILE` 改成 `1`，但 `read` 仍是非阻塞 |
| 输入没反应 | RX 字节没推进 `ring`；或 `osDelay` 太长且 RX 标志没扫到 |
| 中文命令描述乱码 | 源文件编码与串口终端编码不一致 |
